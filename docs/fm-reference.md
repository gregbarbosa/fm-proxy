## `fm count-tokens`

Count the tokens in a prompt, instructions, or transcript.


```
Count the number of tokens using the on-device system model's tokenizer. Supports positional prompts, --text and --image segments, --instructions, and a saved --transcript.

A bare prompt is counted as raw content on its own. Add --instructions or --transcript to instead count the framed request the model actually receives, including the chat-template turn markers the model injects around it.

When stdout is a terminal the output is prefixed with 'Token count: '; when piped or redirected (or when --quiet is passed) only the integer is printed. When no prompt is given on the command line, the prompt is read from standard input if stdin is piped.
```

## `fm schema object`

Generate a structured output schema for an object type.


```
Declares properties sequentially. Each --string, --integer, --double,
or --boolean starts a new property declaration. Follow with
--description, --optional, and/or --array to annotate the property.

  --string <name>       Declare a string property.
  --integer <name>      Declare an integer property.
  --double <name>       Declare a floating-point property.
  --boolean <name>      Declare a boolean property.
  --nested <name>       Declare a property with a nested schema (must be followed by --schema).
  --schema <json>       Provide a structured output schema (after --nested, or after --anyOf for union choices).
  --anyOf               Build an anyOf union schema. Subsequent --schema args become choices.
  --array               Mark the preceding property as an array of that type.
  --description <text>  Set description on the preceding property.
  --optional            Mark the preceding property as optional.

Use dot notation (a.b) in property names to create nested objects.
For example, 'address.street' and 'address.zip' produce an 'Address'
object with 'street' and 'zip' properties.
```

## `fm serve`

Start a Chat Completions API server for Foundation Models.


```
Starts an HTTP server that exposes the Chat Completions API. Any client that supports the Chat Completions API can connect to it. Specify the model per request via the "model" field: "system" (default), "pcc", or — when the server is started with --model-provider (or a configured default model provider) — any model that model provider serves, which is routed upstream. GET /v1/models lists the built-in models alongside the model provider's models.

Use --socket for Unix domain socket transport (recommended for local Python bindings). Use --host/--port for TCP (default).

ENDPOINTS:
  POST /v1/chat/completions  - Chat completions (streaming & non-streaming)
  GET  /v1/models            - List available models
  GET  /health               - Health check
```
